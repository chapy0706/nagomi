# issue-25: スマホ対応の磨き込み

## 概要・背景・目的

20代の主要ユーザー層はスマホネイティブ世代であり、スマホからのアクセスを快適にする。
ただしフロアの2D表示・アバター操作はPC優先の体験であり、スマホでは機能を絞った形で提供する。

「スマホで全機能を使えるようにする」のではなく、「スマホでも自然に使える範囲を最適化する」方針。
過剰な互換性追求はコストに見合わないため、提供範囲を明確に区切る。

## 受け入れ条件

- [ ] レスポンシブデザインが全画面に適用されている
- [ ] モバイル時の主要機能は以下に絞られる
  - ログイン・ログアウト
  - ステータス確認・変更
  - フロアの簡易表示（参加者リスト・トピック表示）
  - 通話への参加（音声のみ）
  - 通報・ブロック
- [ ] フロアの2D表示はスマホでも閲覧可能（ただしアバター移動はPC優先）
- [ ] 通話画面はモバイルレイアウトに最適化されている
- [ ] iOS Safari・Android Chrome での動作確認が完了している
- [ ] Playwright のモバイルビューポートテストでカバーされている
- [ ] アクセシビリティ（タッチターゲットサイズ、コントラスト）が WCAG AA 相当
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- ブレークポイントは Tailwind デフォルト（sm:640px, md:768px, lg:1024px）を採用
- iOS Safari の WebRTC 制約（音声自動再生不可など）を Jitsi 側で確認
- モバイル時はサイドメニューをドロワー形式で表示
- 通話中の画面ロック対策（WakeLock API の利用検討）
- バイブレーション通知の利用検討（招待受信時）
- PWA化は本 issue の範囲外（将来対応）
