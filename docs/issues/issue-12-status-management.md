# issue-12: ステータス管理（手動切り替え + 派生ステータス）

## 概要・背景・目的

ユーザーが自身のステータスを手動で切り替えられるようにする。
ステータスは「ログイン中（available）」「取り込み中（busy）」「離席中（away）」の3種類で、通話中は自動的に「通話中（in_call）」が派生する。

手動ステータスと派生ステータスを分離して保持することが設計の肝。
通話終了後に「通話前のステータス（例: 取り込み中）」に戻す挙動を、状態管理として表現する。

## 受け入れ条件

- [ ] `PresenceState` 値オブジェクトが domain 層に実装されている
- [ ] 手動ステータス（available/busy/away）と派生ステータス（in_call）が分離されている
- [ ] ステータス切り替えUI（ドロップダウンまたはピル形式）が実装されている
- [ ] 通話開始時に自動的に in_call へ遷移する
- [ ] 通話終了時に通話前の手動ステータスへ復元される
- [ ] ステータスに応じてアバターの縁取り色が変わる（Tailwind トークン経由）
- [ ] ステータスは presence データに含まれて他ユーザーに同期される
- [ ] ステータスが busy のユーザーには通話招待が届かない（あるいは「取り込み中です」と表示される）
- [ ] ユニットテストで状態遷移ロジックがカバーされている
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- Tailwind の設計トークンに `status-available` `status-busy` `status-away` `status-incall` を定義する
- 色覚多様性に配慮し、色だけでなくアイコンやテキストでもステータスを表現する
- 自動的に「離席中」になる時間制御（例: 15分操作なし）を入れるか検討
- 「取り込み中」中の通話招待の扱い: 完全ブロックか、通知のみ届くかを検討
- ステータス変更履歴を取るかは本 issue の範囲外（必要なら別途）
