# issue-24: チュートリアル（初回ログイン時のツアー）

## 概要・背景・目的

初回ログイン時に3〜4ステップの軽いツアーを実装する。
nagomi の使い方を教えるだけでなく、文化やマナーを最初に共有する場でもある。

「無理に通話しなくていい」「断ることが正しい使い方」というメッセージを最初に伝えることで、コミュニティの空気を形成する。
機能の説明より、安心感の提供を優先したUI設計とする。

## 受け入れ条件

- [ ] 初回ログイン判定ロジックが利用同意フローと統合されている
- [ ] 3〜4ステップのツアーUIが実装されている（shadcn の Dialog または独自実装）
- [ ] 各ステップの内容
  - ようこそメッセージ（nagomi の存在意義）
  - フロアの歩き方と通話の始め方
  - ステータス切り替えと「気が向かない時の断り方」
  - 通報・ブロック機能の存在（自衛手段としての位置づけ）
- [ ] ツアーはスキップ可能
- [ ] スキップした場合も、後からヘルプメニューから再表示できる
- [ ] ツアーは「次へ」「戻る」で操作でき、キーボードナビゲーションも対応
- [ ] モバイルでも快適に閲覧できる
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- ツアー完了状態は `employees.tutorial_completed_at` のような列で管理
- スキップは「未完了だが表示しない」状態として記録（再表示時の挙動を制御）
- ツアー中のスクリーンショット風画像は、本物のUIに似せた擬似画像を使う
- 文言は最も時間をかけて磨くべき部分。ドラフトの後にチームレビューを必須とする
- 「無理に通話しなくていい」のメッセージは、ツアー外でもフロア入室時に毎回さりげなく表示する案あり
