# issue-26: ログ自動削除バッチ（週次月曜深夜3時・3ヶ月経過判定）

## 概要・背景・目的

プライバシーポリシーで「利用ログは3ヶ月で削除」と定めるため、自動削除バッチを実装する。
削除対象は attendance_logs、call_participation_logs、reports（一定期間後）など。

「運用ルールでの保証」ではなく「コードで自動実行される仕組み」として担保することで、プライバシー保護の信頼性を構造的に確保する。
ユーザーへの説明責任を、技術的な裏付けで支える設計とする。

## 受け入れ条件

- [ ] Supabase の pg_cron 拡張が有効化されている
- [ ] 削除対象のテーブルごとに削除SQLが定義されている
- [ ] pg_cron で毎週月曜深夜3時（JST）に実行されるスケジュールが登録されている
- [ ] 3ヶ月以上経過したレコードのみが削除される
- [ ] 削除実行時のメタログ（削除件数・実行時刻）が別テーブルに記録される
- [ ] 削除メタログは管理者ダッシュボードから確認可能
- [ ] reports は通報対応の都合上、保持期間を1年とする等のテーブル別ルールが明文化されている
- [ ] ローカル環境でも手動実行可能（make コマンドで実行できる）
- [ ] 統合テストで3ヶ月経過レコードのみが削除されることが検証されている
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- pg_cron は Supabase のダッシュボードから有効化が必要
- JST と UTC の時差を考慮し、cron 設定は UTC ベースで記述（月曜 18:00 UTC = 月曜 3:00 JST）
- 削除はソフトデリートではなくハードデリートとする（プライバシー目的のため）
- 削除メタログには個人特定情報を含めない（削除件数のみ）
- バッチ失敗時の検知方法を検討（pg_cron の実行履歴を定期確認）
- アバター画像（Supabase Storage）の削除は別ロジック（退職者のもののみ削除）
- バックアップ対象から3ヶ月以上前のログが除外されるよう、バックアップ運用も合わせて確認
