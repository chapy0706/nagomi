# issue-19: 通報機能（匿名性をスキーマで保証）

## 概要・背景・目的

ハラスメントや不適切な利用への対抗手段として、匿名通報機能を実装する。
通報者の身元を「運用ルール」ではなく「データモデル」で構造的に保護することが本 issue の最重要原則。

通報者IDをDBに保存しない設計を採用する。
SQL レベルで通報者を特定する手段を持たないため、内部関係者であってもデータから通報者を特定できない。
プライバシー保護を機能で担保する nagomi の倫理的設計の中心。

## 受け入れ条件

- [ ] `reports` テーブルのマイグレーションが追加されている
- [ ] テーブルスキーマに通報者ID列が存在しないことが明示的に確認できる
- [ ] reports テーブルは追記のみ（INSERT のみ。UPDATE/DELETE ポリシーを作らない）
- [ ] `SubmitReport` ユースケースが実装されている
- [ ] 通報UIが実装されている（モーダル、フリーテキスト + カテゴリ選択）
- [ ] 通報送信時、サーバ側でも通報者を特定できる情報をログに残さない
- [ ] 対象ユーザーには通報の事実が通知されない
- [ ] 通報は管理者ダッシュボードでのみ閲覧可能（service_role 経由）
- [ ] 通報送信後、通報者には完了メッセージのみ表示（履歴は残さない）
- [ ] 統合テストで通報者特定不可能性が検証されている
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- Edge Function 経由で通報を受け付け、通報者の認証情報をDB書き込み前に剥がす
- アクセスログ等から間接的に通報者が特定されないよう、Vercel Analytics 等のログにも記録しない仕組みを確認
- 通報カテゴリ: ハラスメント、不適切発言、規約違反、その他
- フリーテキスト本文は最大2000文字程度に制限
- 関連情報（通報対象の最近の通話履歴等）を context カラムに JSON で記録（個人特定情報は含めない）
- 通報の重複防止は、IPベース等ではなく実装しない（匿名性優先のため）
