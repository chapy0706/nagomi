# issue-22: 管理者ダッシュボード（集計ビュー設計）

## 概要・背景・目的

管理者が利用状況を把握するためのダッシュボードを実装する。
ただし、個人を特定可能な利用ログは表示しない。集計ビュー経由でのみアクセスする設計とする。

「短期離職低減」という目的に対する効果測定を行いつつ、監視ツールにはしないことが重要。
モダンで視覚的なグラフ表現を採用し、データから示唆を引き出せるUIにする。

なお本 issue は受け入れ条件が多めである。実装着手前に「アクティブ人数推移」「利用傾向」「通報集計」のサブ issue へ分割するか検討すること。

## 受け入れ条件

- [ ] 管理者向けの認可制御が実装されている（特定ロールのみアクセス可能）
- [ ] 集計用のDBビューが定義されている（個人特定情報を含まない）
- [ ] 日次・週次のアクティブ人数推移グラフが実装されている
- [ ] 時間帯別の利用傾向ヒートマップが実装されている
- [ ] 通話発生数の推移グラフが実装されている
- [ ] トピック別の通話比率が円グラフで表示される
- [ ] 通報の集計（カテゴリ別件数、対象別件数）が表示される
- [ ] グラフライブラリは shadcn/ui の Chart コンポーネント（Recharts ベース）を採用
- [ ] レスポンシブで PC・タブレットで見やすい
- [ ] 個別ユーザーの利用ログにアクセスする手段がUI上に一切存在しない
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- 集計ビューは Postgres の VIEW または MATERIALIZED VIEW として定義
- 管理者ロールは Supabase の app_metadata または employees テーブルの role カラムで管理
- ダッシュボードURLは `/admin` 配下とし、middleware でロールチェック
- グラフのデータは初期は SSR で取得、必要に応じて Client 側で更新
- ダッシュボードからのデータエクスポートは将来 issue（issue-29）で対応
- ダッシュボードのアクセス自体もログに残す（誰が管理画面を見たかの透明性）
