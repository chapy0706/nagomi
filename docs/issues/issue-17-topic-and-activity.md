# issue-17: トピック種別の選択と会話可視化

## 概要・背景・目的

通話開始時に会話のトピック（面談 / 悩み相談 / 雑談）を発起人が選択する。
選択されたトピックは外部から見える会話状態に表示され、他のユーザーが「入っていいか」を判断する材料になる。

トピック表示は義務ではなく推奨。
ただし表示することで参加ハードルが下がるため、選択を促すUI設計とする。「面談中」と表示されていれば邪魔しないし、「雑談」なら気軽に混ざれる。

## 受け入れ条件

- [ ] `CallTopic` 値オブジェクトが domain 層に実装されている（counseling / casual / meeting）
- [ ] 通話開始時のトピック選択UIが実装されている
- [ ] トピックは招待ペイロード・通話セッションに含まれる
- [ ] フロア上の通話グループには参加人数・トピック・経過時間が可視化される
- [ ] 発話状況（盛り上がり度）が簡易的に表示される（Jitsi の dominant speaker stats を利用）
- [ ] トピック未選択でも通話開始は可能（推奨だが義務ではない）
- [ ] トピックごとに視覚的な区別がある（色・アイコン）
- [ ] トピック表示はモバイルでも視認できる
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- トピック種別は将来拡張可能なよう union type で定義し、追加時の影響範囲を限定する
- 経過時間はクライアント側で計算（通話開始時刻からの差分）
- 盛り上がり度は「最近30秒の発話イベント数」のような簡易指標で十分
- トピック変更を通話中にできるようにするかは要検討（複雑化のリスクあり、初期はYES固定）
- 「面談」「悩み相談」は秘匿性が高いため、参加者リストの可視性をトピックで切り替えるかも検討
