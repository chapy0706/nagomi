# issue-23: ユーザー満足度測定機能

## 概要・背景・目的

「nagomi が短期離職低減に寄与しているか」を測る指標として、ユーザー満足度を定期的に取得する。
セッション終了時の簡易アンケートと、月次のNPSライクな質問の2軸で集計する。

回答は匿名化し、個人を特定する情報を持たない設計とする。
ユーザーが「正直に答えても自分が特定されない」と感じられることが、データの質を上げる前提条件。

## 受け入れ条件

- [ ] `satisfaction_responses` テーブルのマイグレーションが追加されている
- [ ] テーブルスキーマに employee_id 列が存在しないことが明示的に確認できる
- [ ] satisfaction_responses は追記のみ（INSERT のみ。UPDATE/DELETE ポリシーを作らない）
- [ ] セッション終了時の簡易アンケートUIが実装されている（1〜5の評価 + 任意コメント）
- [ ] アンケートは月に最大1回までしか表示されない（同一ユーザーへの頻度制御）
- [ ] アンケートはスキップ可能
- [ ] 月次のNPSライクな質問（任意・別途トリガー）が実装されている
- [ ] アンケート結果が管理者ダッシュボードの集計に反映される
- [ ] 統合テストで匿名性が保証されている
- [ ] アンケート文言は柔らかく、評価強制感のないトーン
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- 「同一ユーザーに月1回」の制御はクライアント側で行う（サーバ側で記録すると匿名性が損なわれる）。具体的な保存手段は実装時に検討
- クライアント側の表示制御データが消えると再表示されてしまうが、許容する（厳密な制御はしない）
- 回答送信は Edge Function 経由で、認証情報を剥がしてからDB書き込み
- NPSライクな質問は「nagomi をどのくらいの確率で同僚におすすめしますか？(0〜10)」のような形式
- アンケート文言は心理的安全性を意識し、「正直な気持ちを聞かせてください」のような優しいコピー
- 自由記述コメントは検閲しないが、攻撃的な内容が含まれる場合に備えてモデレーションのフックを残す
