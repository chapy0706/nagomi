# issue-20: 在席ログ記録（AttendanceLog）

## 概要・背景・目的

ログイン・ログアウトのタイムスタンプを記録し、管理者が「派遣社員がいつどれくらい参加していたか」を把握できるようにする。
厳格な勤怠管理ではなく、業務影響の把握ができる程度の精度を目標とする。

ユーザー自身は自分の記録を閲覧可能だが、改竄不可とする。
RLS で SELECT のみ許可し、UPDATE/DELETE は service_role のみとする。

## 受け入れ条件

- [ ] `attendance_logs` テーブルのマイグレーションが追加されている
- [ ] `AttendanceLog` エンティティが domain 層に実装されている
- [ ] RLS により、ユーザーは自分のレコードのみ SELECT 可能
- [ ] RLS により、ユーザーは自分の INSERT のみ可能
- [ ] UPDATE/DELETE は service_role のみ可能
- [ ] `RecordLogin` ユースケースが実装され、ログイン成功時に呼ばれる
- [ ] `RecordLogout` ユースケースが実装され、明示ログアウト時に呼ばれる
- [ ] presence の disconnect イベントをサーバ側で検知し、5分後に logged_out_at を埋める
- [ ] ソース区分（explicit / inferred）で記録方法が明示される
- [ ] ユーザー自身の在席履歴閲覧画面が実装されている
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- presence の disconnect 検知は Supabase Edge Function で実装する
- ネットワーク不安定での頻繁な切断・再接続をマージするロジックを入れる（5分以内の再接続は同一セッション扱い）
- タブを閉じた・PCをスリープした等のケースも presence の disconnect で検知できる
- 保存期間は3ヶ月（後続の自動削除バッチで対応）
- ユーザー閲覧画面では「今月の合計時間」「日別の在席時間」程度の集計を表示
- 管理者は集計ビュー経由でアクセスし、個別ユーザーの詳細ログには触らない設計
