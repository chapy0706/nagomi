# issue-09: アバター表示と初期配置ロジック

## 概要・背景・目的

ログイン後、ユーザーは2Dフロア上にアバターとして表示される。
本 issue ではアバター画像のアップロード機能、表示名管理、初期配置ロジックを実装する。

初期配置は「空いている場所」をドメインサービスで決定する。
ランダム配置だと既存ユーザーと重なる可能性があり、入室体験が悪くなるため、衝突回避ロジックを最初から組み込む。

## 受け入れ条件

- [ ] `Avatar` エンティティが domain 層に実装されている
- [ ] `DisplayName` 値オブジェクトが実装されている（1〜30文字、禁止文字チェック）
- [ ] アバター画像のアップロード機能が実装されている（Supabase Storage 利用）
- [ ] アバター画像のサイズ制限・形式制限が実装されている（例: 2MB以下、png/jpg/webp）
- [ ] 初期表示名は「User{番号}」形式で自動生成される
- [ ] 表示名の変更機能が実装されている
- [ ] 初期配置ロジックが domain サービスとして実装され、既存アバターとの衝突を回避する
- [ ] アバターコンポーネントが Tailwind + shadcn で実装されている
- [ ] アバター画像未設定時のデフォルト画像（DiceBear 等の抽象的なもの）が表示される
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- Supabase Storage の無料枠（1GB）を意識し、画像は適切にリサイズしてから保存する
- アップロード時にクライアント側でリサイズ（canvas API）してからアップロードする方針
- 表示名の禁止文字は「他人になりすませる文字列」を中心に検討（管理者名、システム文字列など）
- アバター画像のキャッシュ戦略（CDN経由、長期キャッシュ）
- 初期配置の衝突回避は、空きスペースを探索するアルゴリズムを ProximityDetector に類似する形で実装
- 退職者のアバター画像は削除バッチで合わせて消す（後続の運用 issue で対応）
