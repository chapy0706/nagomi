# issue-15: 招待の承諾・拒否・失効処理

## 概要・背景・目的

招待を受けた側の挙動を実装する。
承諾すれば通話に接続し、拒否なら静かに招待を閉じる。30秒で自動的に失効する。

拒否時の挙動には特に配慮が必要。
拒否理由を相手に伝えない、拒否したことを通知しないことで、断ることへの心理的ハードルを下げる。「今は話したくない」が普通の選択肢として成立する空間にする。

## 受け入れ条件

- [ ] `AcceptCallInvitation` ユースケースが実装されている
- [ ] `DeclineCallInvitation` ユースケースが実装されている
- [ ] `ExpireStaleInvitations` ユースケースが実装されている
- [ ] 招待受信時のモーダルUIが実装されている（招待者の表示名・アバター・トピック表示）
- [ ] モーダルには「参加する」「今はやめておく」「ブロックする」の3つの選択肢がある
- [ ] 拒否時には招待者への通知は行わない（招待が単に消える）
- [ ] 拒否は「断ること」のネガティブさを感じさせない文言で表現される
- [ ] 30秒経過後、招待は自動的に失効しモーダルが閉じる
- [ ] 承諾時には VideoRoomGateway.join が呼ばれ、通話画面に遷移する
- [ ] 招待モーダル表示中に他の招待が来た場合の挙動が定義されている（後着拒否 or キューイング）
- [ ] `make verify` がエラーを発生させない

## 技術的な検討事項

- 失効処理はクライアント側のタイマーで実装（サーバ側で失効状態を厳密管理する必要は薄い）
- 「ブロックする」を招待モーダルから直接できるようにすることで、悪意ある反復招待への対抗手段を即時提供する
- 招待モーダルの表示位置はモバイルでは画面中央、PCでは右下のトーストのようなUIも検討
- 招待を放置（モーダルを閉じずに無視）した場合は失効扱いとする
- 通話開始時のサウンド通知をどうするか検討（うるさくならないよう、控えめなチャイム）
