# ADR-006: 通話開始に必ず合意ステップを挟み、近接自動接続を採用しない

## Context

nagomi は2Dフロア上でアバターが近づいたときに通話が始まる、という体験を持ちうる。
oVice のような仮想オフィスサービスの多くは「距離が近づいたら自動で音声が聞こえる」
という近接自動接続モデルを採用している。

一方 nagomi の主要ユーザーは業務終わりや休日に任意でアクセスする20代の新人であり、
「予期せず声をかけられる」「断りにくい雰囲気になる」という体験が、
かえって来訪のハードルを上げるリスクがある。

通話開始の設計は、プロダクトのコミュニティの空気そのものを決める。

## Decision

すべての通話開始に **明示的な合意ステップ** を必須とする。
近接自動接続は採用しない。

具体的には以下の2形式で実装する。

- フロアでの1対1・小グループ: 招待（IssueCallInvitation）→承諾（AcceptCallInvitation）→接続
- 会議室への入室: ロビー画面（デバイス確認・同意再確認）→「参加する」→接続

どちらのパスも、ユーザーが「参加する」を明示的に選択するまで通話は始まらない。

## Rationale

### 合意ステップを必須にする理由

**「断れる」がデフォルトである環境を作る。**
断ることを「失礼」と感じさせる空間になると、来ること自体をやめてしまう。
招待を断る選択肢を「今はやめておく」という自然な言葉で用意し、
断ったことが相手に通知されない設計にする。
「断っても気まずくならない」という体験が、繰り返し来てもらえる条件になる。

**心理的安全性を機能で担保する。**
「安全なコミュニティを目指します」という宣言より、
「ユーザーが断るための動線が常に用意されている」という設計の方が強い。
「参加する」「今はやめておく」「ブロックする」の3択を招待モーダルに置くことで、
自衛手段が常に手元にある状態にする。

**20代の新人層は「予期せぬ通話」に強いストレスを感じる。**
スマホネイティブ世代は、音声通話を「事前に準備するもの」と認識している傾向がある。
急な着信への抵抗感は、仮想オフィスの近接自動接続でも同様に発生する。
ロビー画面は「心の準備の時間」を構造として提供する。

### 近接自動接続を不採用とした理由

近接自動接続は「偶然の出会いの演出」としては効果的だが、
nagomi の文脈では「逃げ場のない状況の演出」になりうる。

「取り込み中」のステータスにしていても近づいただけで音声が入ってくる、
という体験は、ステータス管理の意味をなくす。合意ベースの設計であれば、
「取り込み中」のユーザーへの招待は届かないか、届いても断れる。
ステータスの自己管理が実際に機能する。

## Consequences

### 良い結果

- 「断ること」が普通の選択肢として成立する空間になる
- ステータス（取り込み中・離席中）が通話接続の制御に実際に機能する
- 来訪のハードルが下がり、「なんとなく立ち寄る」行動を促せる可能性が高まる

### 引き受けるトレードオフ

- 「たまたま近くにいた人と気づいたら会話していた」という偶発的な出会いの体験は弱くなる。
  これは意図的なトレードオフである
- 招待→承諾のフローが存在するため、通話開始までのステップが増える。
  UXの摩擦が増えることは承知の上で、安全性を優先する

### 今後の見直し条件

以下のいずれかが発生した場合、本 ADR を見直す。

- ユーザーフィードバックで「もっと気軽に話せる仕組みが欲しい」という声が多数を占め、
  近接自動接続のオプトインを検討する余地が生まれた
- ステータス管理の自由度が上がり、「近接自動接続 + 即座にミュート可能」のような
  中間的な体験設計が検討に値するようになった
