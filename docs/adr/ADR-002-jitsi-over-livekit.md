# ADR-002: 通話基盤に Jitsi Meet を選択し、LiveKit・Daily・Agora を不採用とした

## Context

nagomi はリアルタイム音声通話を中核機能として持つ。
要件は「同時に複数のグループが独立して通話できること」「50人規模で動作すること」
「業務終わりや休日の利用を想定した基本無料運用」の3つが重なる。

WebRTC SFU（Selective Forwarding Unit）を使った通話基盤の選定において、
自前ホストの運用コストと、商用サービスの無料枠制約の両方を検討する必要があった。

## Decision

通話基盤として **Jitsi Meet（meet.jit.si の公開インスタンスを iframe 埋め込み）** を採用する。
LiveKit・Daily・Agora は本 ADR の検討時点で不採用とする。

## Rationale

### Jitsi Meet を選んだ理由

**完全無料で人数制限がゆるい。**
meet.jit.si は Jitsi の公開インスタンスであり、ゲスト参加が可能で、
同時数十〜100人規模の通話に対応する。月額費用ゼロで運用できる。

**iframe 埋め込みと External API が充実している。**
`external_api.js` を使うことで、通話の開始・終了・カメラ制御・
スピーカーイベントの受信といった操作を nagomi のアプリ側から制御できる。
Jitsi のルームに入ったまま、フロアの2D描画をオーバーレイで重ねる構成が成立する。

**起動時のカメラOFFをURLハッシュで制御できる。**
`#config.startWithVideoMuted=true` の指定だけでカメラOFFをデフォルトにできる。
「就業後の時間は音声のみでゆるく話す」という nagomi のトーンを、
設定1行で体現できる。

**ルームは入室で生まれ退室で消える設計が自然に合う。**
Jitsi のルームはサーバー上の常駐実体ではなく、最初の1人が入室した瞬間に生成され、
最後の1人が退室した瞬間に消える。nagomi の固定部屋（会議室・ラウンジ）は
URL の規則で決まる文字列で表現できるため、事前にルームを立ち上げる運用は不要になる。
これはインフラをシンプルに保つことに直結する。

**将来的に自前ホストへの移行パスがある。**
`VideoRoomGateway` ポートの実装を差し替えれば、アプリ側の変更なしに
自前 Jitsi サーバーや他サービスへの移行ができる。依存が infrastructure 層に閉じている。

### LiveKit を不採用とした理由

LiveKit Cloud の無料枠は月5,000 participant-minutes が上限。
50人 × 1時間の交流会を1回開くだけで3,000分消費する計算になり、
月に数回の大規模交流会を想定すると即座に上限に達する。
自前ホストも選択肢だが、サーバー運用コストが発生し無料運用の前提と矛盾する。

### Daily を不採用とした理由

無料枠の制約が LiveKit と同水準で、nagomi の利用規模に対して現実的でない。
iframe 埋め込みは可能だが、Jitsi と比べて制御の自由度が低く、
カメラOFFのデフォルト設定などを hagomiのUXに合わせて調整しにくい。

### Agora を不採用とした理由

無料枠はあるが、分単位の課金モデルに移行した場合のコスト試算が
nagomi の規模では合わない。また API が複雑で、
今回のような「iframe に権限を絞って埋め込む」構成に最適化されていない。

## Consequences

### 良い結果

- 月額コストゼロで通話機能を提供できる
- iframe + External API でアプリ側の制御が十分に効く
- カメラOFFデフォルト、ツールバーの絞り込みなど、UXに直結する設定が柔軟
- ポートで抽象化してあるため、将来の乗り換えコストが小さい

### 引き受けるトレードオフ

- meet.jit.si は公開インスタンスのため、SLA の保証がない。
  サービス品質は Jitsi コミュニティの運用に依存する
- 大規模な商用利用には不向き。nagomi が成長して利用が増えた場合、
  自前ホストへの移行判断が発生しうる
- 通話品質の細かいチューニング（コーデック選択・帯域制御など）は制限される

### 今後の見直し条件

以下のいずれかが発生した場合、本 ADR を見直す。

- meet.jit.si の品質・可用性が業務利用に支障をきたすレベルに低下した
- 利用規模が拡大し、自前ホストまたは商用 SFU のコストが正当化できるようになった
- VideoRoomGateway ポートを活かした別実装への移行要件が発生した
