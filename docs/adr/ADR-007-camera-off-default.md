# ADR-007: 通話開始時のカメラを OFF デフォルトとした

## Context

nagomi の利用時間帯は「業務終わりや休日」を想定している。
ユーザーは職場や自宅などのプライベートな環境からログインする。

通話を始める相手は、必ずしも親しい間柄ではなく、
たまたま同じ時間にログインしていた正社員派遣同士である。
そのような関係性の浅い相手と、いきなりビデオ通話で顔を合わせることには、
心理的なハードルがある。

また、業務後の疲れた状態や、部屋の映り込みなどを気にせず気軽に参加できることが、
「ふらっと立ち寄れる」という体験価値を支える前提条件になる。

通信量の観点でも、音声のみの通信は映像を含む場合と比較して大幅に小さい。
スマホからの接続も想定しているため、通信量への配慮は利便性に直結する。

## Decision

通話開始時のカメラを **OFF（映像なし）デフォルト** とする。

マイクは ON デフォルトとする（音声通話が主目的のため）。
カメラの ON/OFF はユーザーが任意に切り替えられるが、
nagomi のUX指針として「声だけでゆるく話せる場所」を明示する。

技術的には Jitsi Meet の URL ハッシュパラメータで制御する。

```
#config.startWithVideoMuted=true
&config.startWithAudioMuted=false
```

この意図は VideoRoomGateway ポートの引数として表現し、
インフラ層の JitsiVideoRoomGateway がそれを URL ハッシュに変換する。

## Rationale

### カメラ OFF デフォルトを選んだ理由

**利用シーンとの一致。**
業務後・休日・プライベートな環境からの接続では、
カメラを ON にすることへの心理的ハードルが高い。
「参加する前にカメラをOFFにしなければ」という操作を強いると、
それ自体が通話参加へのブレーキになる。
デフォルトを OFF にすることで、ブレーキを取り除く。

**「声だけで話せる」文化の明示。**
カメラ OFF デフォルトは技術的な設定であると同時に、
「ここは映像を求めない場所だ」というプロダクトの意思表示でもある。
ユーザーは最初からカメラを気にしなくてよいと分かり、
参加のハードルが下がる。

**通信量への配慮。**
スマホネイティブ世代のユーザーが多く、モバイル回線からの接続も想定される。
音声のみの通信は、映像を含む場合と比べて通信量が大幅に小さく、
モバイルデータの消費を抑えられる。

**実装の容易さ。**
Jitsi の URL ハッシュパラメータで実現できる。
複雑な実装を要せず、VideoRoomGateway の `initialMute` オプションとして
ドメイン側から意図を表現できる。

### カメラ ON デフォルトを採用しなかった理由

顔が見える方が親密感が生まれ、交流が深まる、という考え方もある。
しかし nagomi の目的は「深い交流の場を作ること」ではなく
「立ち寄るハードルを下げること」にある。

カメラ ON デフォルトは「来た人をより活発に交流させる」かもしれないが、
「来る人を減らす」リスクの方が大きいと判断した。
来てもらうことが最優先であり、来た後の体験を重くしすぎない。

## Consequences

### 良い結果

- 通話参加へのハードルが下がる。気軽に声だけで参加できる
- プライベートな環境（部屋・服装・顔の状態）を気にせず参加できる
- モバイル回線でも通信量を抑えられる
- 「声だけでゆるく話せる場所」という文化が最初から共有される

### 引き受けるトレードオフ

- カメラを ON にしたいユーザーは、手動で ON にする操作が1ステップ増える
- 顔が見えないことで、関係構築のスピードが遅くなる可能性がある
- テキストやビデオを重視するユーザー層には物足りない体験になりうる

### 今後の見直し条件

以下のいずれかが発生した場合、本 ADR を見直す。

- ユーザーフィードバックで「カメラを ON にしたいが手順が分からない」
  という声が一定数集まった場合（UX の改善で対応できるが、デフォルトの見直しも検討）
- nagomi の利用が定着し、ユーザー間の関係性が深まった段階で、
  カメラ ON を推奨するフェーズへの移行を検討する場合
